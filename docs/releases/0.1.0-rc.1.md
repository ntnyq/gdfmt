## Changes reviewed for the candidate

- Accept integer-valued decimal/exponent JSON configuration numbers consistently
  with Schema, retaining range validation and partial-configuration restrictions.
- Validate incompatible CLI arguments before I/O; preserve JSON diagnostic routing
  and keep LSP/formatting switches mutually exclusive.
- Reject unsupported JavaScript own properties, including non-enumerable and
  symbol properties; align WASM initialization declarations and runtime checks.
- Refuse editor edits that cannot preserve mixed line endings exactly, retain
  whole-document formatting, and document desktop/Web configuration and trust
  differences with regression coverage.
- Harden version synchronization around the real workspace version field and
  independent numeric extension version. Fix the legacy recovery test fixture
  to use matching source manifests even during an uncommitted version update;
  production recovery still rejects version/hash/revision mismatches.
- Narrow the project-trial comparator's inner-class `extends` normalization to
  the corresponding header colon; retain body/dictionary/suite colon differences.
- Refresh bilingual installation, API, editor, migration and release documentation.

## Support, defaults and migration

The candidate retains the [planned 0.1.0 support and migration contract](0.1.0.md):
Rust 1.88+, CLI, Node 22.13+ on 22.x or Node 24.x, browser ESM/module Workers,
stdio LSP, VS Code 1.96+ desktop and a separate Web extension. Native targets are
macOS ARM64/x64, Windows x64 MSVC and Linux x64 glibc/musl; grammar profiles are
Godot 4.3–4.7, default 4.7.

**Default formatting style is unchanged:** width 100, tabs at width 4, LF for
configuration-based hosts, at most two existing blank lines and a final newline.
The pure Rust facade preserves source EOLs by default. Existing punctuation,
literal spelling, comments and protected-region bytes remain preserved. Width
is a target at supported break points, not a hard limit.

For migration from `gdformat`, start with a clean project, translate settings
manually into `.gdfmtrc.json`, inspect `gdfmt --diff .`, apply the change separately
from behavior changes, and run the project's Godot checks. See the
[detailed migration steps](0.1.0.md#migrating-from-gdformat).

## Known limits and remaining acceptance

There is no full Godot compatibility or runtime-equivalence claim, lint/semantic
fixing, range formatting, Godot 3 support or general WASI/Bun/Deno promise. Web
configuration rejects overrides, configuration ignore fields and discovered
EditorConfig; mixed EOL output may need the CLI. Long expressions and preserved
content can exceed line width. See the [complete limits](0.1.0.md#known-limitations).

Local rc.1 checks are recorded in the preparation report. They do not replace
Linux/Windows/Intel/Alpine CI, the ten Node consumer receipts, six frozen VSIX
files or fresh registry installation after an authorized publication. No `tag`,
publish, channel promotion or Marketplace upload is part of this preparation.
