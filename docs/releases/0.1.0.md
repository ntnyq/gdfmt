# gdfmt 0.1.0 release notes

[简体中文](../zh/releases/0.1.0.md)

**Draft — 0.1.0 has not been published.** The prepared source uses core
**0.1.0** and independent extension **0.2.1**, following the published
[0.1.0-rc.1 candidate](0.1.0-rc.1.md). See the
[clean-source CI report](../research/0.1.0-ci.md). Default formatting and public
API/Schema contracts are unchanged. Source CI and clean project trials passed;
PR merge and final tagged-artifact acceptance remain tracked in the
[release checklist](https://github.com/ntnyq/gdfmt/blob/main/RELEASE_CHECKLIST.md).

gdfmt formats UTF-8 GDScript `.gd` files with a shared Rust core. Writable output
must reparse, retain syntax and comment relationships, and produce identical
output on a second formatting pass. The release covers full-script formatting,
project configuration, command-line checks and editor-buffer integrations.

## Supported hosts

| Host            | Scope                                                                                                                                                                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rust            | The `gdfmt` facade provides pure text formatting; configuration/workspace crates add explicit project resolution. Minimum supported Rust is 1.88, edition 2024; source development uses the pinned toolchain.                                  |
| CLI             | The `gdfmt_cli` Cargo package installs `gdfmt`: format files, check, preview diffs, format stdin, inspect configuration and emit JSON reports.                                                                                                 |
| Native Node.js  | `@gdfmt/gdfmt`: ESM/CommonJS, TypeScript declarations, sync/async text formatting and configuration resolution. Node 22.13+ on 22.x or Node 24.x; keep optional native dependencies enabled.                                                   |
| Browser/WASM    | `@gdfmt/wasm`: browser ESM and module Workers, asynchronous initialization and synchronous formatting. No shared memory or cross-origin isolation requirement. Explicit-byte Node loading is also supported. Browser acceptance uses Chromium. |
| Desktop editors | Formatting-only stdio LSP and VS Code 1.96+ desktop extension, including matching remote SSH/WSL/container extension hosts. Native VSIX bundles its formatter.                                                                                 |
| Web editors     | Separate VS Code Web VSIX with bundled WASM Worker, virtual workspaces, unsaved buffers, save formatting, undo and UTF-16 diagnostics.                                                                                                         |

Native npm packages and desktop VSIX targets cover macOS ARM64/x64, Windows x64
MSVC, and Linux x64 glibc/musl. Linux glibc artifacts use Ubuntu 24.04 as their
baseline; older glibc versions are not validated. Select a VSIX for the extension
host's platform, including remote hosts. A built native VSIX needs no separate
Node installation; a selected workspace npm CLI uses the extension host's Node.
For 0.1.0, frozen GitHub Release VSIX files are the recommended delivery baseline;
Marketplace stable publication is a separate follow-up. The existing Marketplace
listing is a prerelease, not the final core release. Browser-only installation
uses the Gallery or a supported developer sideloading route; see editor setup.

See [installation](../guide/index.md), [Node](../reference/node.md),
[WASM](../reference/wasm.md) and [editor setup](../guide/integrations.md).

## Godot grammar profiles

Profiles are **4.3, 4.4, 4.5, 4.6 and 4.7**, with **4.7** as the fixed default.
Set `language.godotVersion` to your project's profile. Profiles enforce verified
syntax introduction boundaries, such as typed dictionaries in 4.4, abstract
declarations/rest parameters in 4.5, and multiline-export hints in 4.6.

Godot 3.x, unknown versions, patch strings such as `4.7.2`, and `latest` are not
configuration values. Profiles do not claim complete Godot compatibility, project
analysis or runtime equivalence. See [version gates](../reference/language-versions.md)
and [compatibility](../reference/compatibility.md).

## Default formatting style

The reviewed defaults retain the existing prerelease style:

| Setting                     | Default and behavior                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------- |
| Line width                  | `100`, a target at supported list/argument break points rather than a hard maximum.    |
| Indentation                 | Tabs, with tab width `4`; applies to suites and continuations.                         |
| Structural newlines         | LF; one final newline on nonempty files.                                               |
| Existing blank lines        | At most `2`; leading/trailing empty lines are removed.                                 |
| Arrays, dictionaries, enums | `auto` layout; lists wrap at supported break points.                                   |
| Dictionary spacing          | `compact`, without padding inside single-line braces.                                  |
| Trailing-comma layout       | `auto`; comma tokens are retained, never inserted or removed.                          |
| Definition spacing          | `preserve`; existing gaps remain subject to the blank-line cap.                        |
| Lambda bodies               | `auto`; one simple, comment-free statement can remain inline, other bodies use blocks. |
| Inline comments             | One space between code and a trailing comment.                                         |

Named functions and control-flow suites use multiline bodies. Literal spelling,
existing punctuation, BOMs, comment text/order/attachment, multiline-string bytes
and protected-region bytes are preserved. Layout options do not rewrite quotes
or add parentheses to force wrapping. Pure Rust `FormatOptions` defaults to
preserving source line endings; CLI/Node/WASM configuration defaults to LF.

Paired standalone `# gdfmt: formatter-off` / `# gdfmt: formatter-on` comments
preserve selected regions, including marker lines. Those regions must still parse;
nested or unmatched directives produce no writable output. See
[formatting](../reference/formatting.md) and [all configuration options](../guide/configuration.md).

## Migrating from gdformat

gdfmt has its own layout rules. Matching width and indentation does not make its
output identical to gdtoolkit's `gdformat`, and configuration files are not
interchangeable. Keep `gdlint` or other analysis tools if you use them: gdfmt does
not replace lint rules.

1. Pin the same gdfmt version locally and in CI. Start from a clean working tree
   and make the initial formatting change separately from behavior changes.
2. If neither gdfmt configuration filename exists, run `gdfmt init`. Edit the
   resulting `.gdfmtrc.json` for the project's profile and layout. For example,
   a Godot 4.5 project using two spaces can use:

   ```json
   {
     "schemaVersion": 1,
     "root": true,
     "language": { "godotVersion": "4.5" },
     "format": { "lineWidth": 100, "indentStyle": "space", "indentWidth": 2 }
   }
   ```

   Translate settings manually; gdfmt does not discover `gdformatrc` or `.gdformatrc`.
   The upstream [gdformat CLI/configuration implementation](https://github.com/Scony/godot-gdscript-toolkit/blob/master/gdtoolkit/formatter/__main__.py)
   documents the old settings and switches used in this mapping:

   | Existing gdformat setting       | gdfmt equivalent                                                                              |
   | ------------------------------- | --------------------------------------------------------------------------------------------- |
   | `line_length` / `--line-length` | `format.lineWidth`, integer 40–320.                                                           |
   | `use_spaces` / `--use-spaces`   | `format.indentStyle: "space"` plus `format.indentWidth`, integer 1–8; use `"tab"` for tabs.   |
   | `excluded_directories`          | Review paths and write gitignore-style `.gdfmtignore` rules; check the actual selected files. |
   | `safety_checks` / `--fast`      | No bypass: gdfmt always validates writable output.                                            |

3. Review ignore rules and any formatter-suppression comments. Native discovery
   honors local ignores and always excludes `.git`, `.godot`, `node_modules` and
   `target`; old exclusion lists are not imported. Use gdfmt's paired markers
   where exact layout must remain. Use `gdfmt explain-config path/to/script.gd`
   to inspect effective settings and whether a path is ignored.
4. Run `gdfmt --diff .`, inspect representative comments, lambdas, long lines and
   protected regions, then run `gdfmt .` to apply the reviewed configuration.
   A preview exits 1 when formatting differs; exit 2 means arguments,
   configuration, I/O/internal failures or no selected inputs. Run your usual
   Godot project checks and tests after formatting.
5. Change CI/hooks to `gdfmt --check .` and VS Code's GDScript default formatter to
   `ntnyq.gdfmt`. Stop alternating formatters on the same files. A check exits 0
   for clean input, 1 for source/directive errors or formatting differences, and
   2 for host/configuration failures; batches choose the highest code.

Configuration precedence is defaults, EditorConfig, JSON/JSONC base fields, then
matching overrides. Verify it before adopting a converted configuration. For an
external editor, pass the unsaved buffer via `gdfmt --stdin-filepath path/to/file.gd`
and apply stdout only on exit 0. See [file selection](../guide/configuration.md#ignore-rules-and-input-selection)
and [CI/editor integration](../guide/integrations.md).

## Known limitations

- Type/name resolution, resources, inheritance/abstract overrides and runtime
  behavior remain Godot's responsibility. Annotation values are only partially
  checked; Unicode confusable-keyword security checks are not reproduced.
- Long expressions/chains, indivisible tokens/type references and retained
  comments/literals/protected regions can exceed the width target. There is no
  quote conversion, comma insertion/removal, lint engine or semantic auto-fix.
- Scene/resource files, shaders, embedded GDScript, and `namespace`/`trait`
  declarations are outside the supported scope.
- Editor formatting is whole-document only. VS Code cannot represent mixed EOL
  output losslessly; desktop and Web refuse such edits. `preserve` can help with
  uniform input, but exact mixed output may require the CLI. Buffer loading may
  already normalize line endings.
- Web configuration is confined to the owning workspace and rejects `overrides`,
  configuration `ignore` (even empty arrays) and discovered EditorConfig. Ignore
  files do not exclude opened Web documents. Desktop workspace `configPath`
  requires trust; packaged Web allows it in untrusted workspaces within the same
  workspace boundary and ignores `serverPath`.
- Host text formatting has a 16 MiB source limit. Web configuration allows 1 MiB
  per file, 16 MiB total reads, 32 inheritance levels, 128 applied layers and
  128 discovery directories. WASM formatting blocks its calling thread; use a
  Worker for larger inputs. Bun, Deno and general WASI hosts are not promised.

Text APIs return structured diagnostics and no output on source/invariant errors;
invalid arguments throw/reject. JavaScript spans are half-open UTF-8 byte offsets,
while LSP/editor positions are UTF-16. Apply API output only when it is non-null.
A successful format/check is not a substitute for validating the project in Godot.
