# 0.1.0 installation and documentation review

[简体中文](../zh/research/0.1.0-documentation-review.md)

Reviewed on 2026-10-23 against the `0.1.0-alpha.6` working tree based on
`6c11445a329b688f27fd6693a3c6314ffeedce64`, including the preceding contract fixes.
The bilingual instructions now match this baseline. Versioned examples and
registry channels still need checking when choosing the final release candidate.

Follow-up: the [distribution review](0.1.0-editor-distribution-review.md) corrected
packaged Web trust and browser installation guidance using actual VSIX manifests;
the current guides include that correction.

## Corrections

| Area                   | Correction                                                                                                                                                                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Installation           | Document explicit Cargo prerelease versions and the `gdfmt_cli` package / `gdfmt` executable distinction. Add npm runtime requirements, the WASM install command and reproducible CI installation using a lockfile or reviewed revision.                                |
| Source builds          | Document dependency installation, the pinned Rust toolchain and repository pnpm version, plus wasm-pack and the WASM target for Web builds. Installing a built native VSIX needs no separate Node installation.                                                         |
| Schema export          | Replace the incorrect `gdfmt/schema.json` module specifier with `@gdfmt/gdfmt/schema.json` in both Node references and the npm README. Verify its ESM resolution from an installed package.                                                                             |
| Configuration examples | Explain how to create inherited base/team files before running the examples. Validate all ten bilingual configuration blocks with the actual CLI.                                                                                                                       |
| API examples           | Check `resolution.ignored` in the npm README before formatting; identify layout options as members of `options.format`. Explain omitted arguments versus explicit `undefined` property values.                                                                          |
| Declarations           | Add JSDoc for numeric ranges/defaults, structural newlines, byte comparison, WASM helper limits and configuration metadata. Signatures and runtime behavior are unchanged by this documentation review.                                                                 |
| Editor setup           | Explain source prerequisites, the remote extension host's native target and core-version VSIX filenames. Untitled buffers use default configuration, but their desktop session can use a trusted global `serverPath`; it does not always select the bundled executable. |

The previous CI text assumed published packages were unavailable. At review time,
the [native npm `next` endpoint](https://registry.npmjs.org/@gdfmt%2Fgdfmt/next) and
[WASM npm `next` endpoint](https://registry.npmjs.org/@gdfmt%2Fwasm/next) both returned
`0.1.0-alpha.6`. The [Cargo package metadata](https://crates.io/api/v1/crates/gdfmt_cli)
reported that prerelease as newest and no stable version. These are dated checks,
not a promise that moving tags remain fixed. Final stable-channel instructions
remain a publication checklist item.

## Verification

- All ten JSON/JSONC examples from the root READMEs and configuration guides
  resolved successfully through `gdfmt explain-config`, with their inherited files
  provided. Both languages' quickstart and layout examples matched exact CLI output.
- Five native API documentation snippets and the scoped Schema export ran against
  an installed local tarball. Three explicit-byte Node/WASM snippets also ran against
  the installed WASM tarball. The three VS Code settings examples matched the
  contributed language/formatter identity and format-on-save setting.
- `pnpm test:npm`: all eight local `darwin-arm64` consumer tests passed, including
  installed ESM/CJS declarations and CLI behavior.
- `pnpm test:wasm`: 1,465 fixture/profile cases passed in Node and Chromium, plus
  Worker, limits and installed declaration checks.
- `pnpm typecheck`, `pnpm typecheck:docs` and `pnpm docs:build` passed. Bilingual
  checklist entries match (22 items, seven complete), local report/checklist links
  exist, and `git diff --check` passed.

No formatter implementation, default style, configuration acceptance, public
signature or package version changed in this review. Full candidate matrices,
registry installation of final artifacts, Marketplace publication and the final
documentation deployment remain separate release gates.
