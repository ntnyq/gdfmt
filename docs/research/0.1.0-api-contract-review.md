# 0.1.0 CLI, API and version contract review

[简体中文](../zh/research/0.1.0-api-contract-review.md)

Reviewed and fixed on 2026-10-23 against the `0.1.0-alpha.6` working tree, based
on commit `6c11445a329b688f27fd6693a3c6314ffeedce64` plus the preceding release
checklist and style/Schema fixes. The contracts below are reviewed for 0.1.0;
candidate artifacts still require their own complete release validation.

## Reviewed contracts

| Surface                 | Contract                                                                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CLI entry points        | Standalone and npm CLI call `gdfmt_cli::run`; process termination stays in the executable entry points. No command/paths formats the current directory.                                                                                          |
| CLI exit codes          | 0 for success, 1 for source/directive errors or read-only differences, 2 for arguments/configuration/I/O/internal failures or no inputs; batches use the highest code.                                                                           |
| CLI output              | Human errors use stderr. JSON reports use stdout with schema version 1 and UTF-8 byte spans. Help/version remain plain text. LSP uses framed JSON-RPC instead of a reporter.                                                                     |
| Rust facade             | Explicit `FormatRequest`, no discovery or filesystem writes. Writable output passes reparse, syntax/comment preservation and idempotence checks. `Some("")` is successful empty output.                                                          |
| JavaScript text APIs    | Sync and async native functions share results; async work uses libuv. WASM uses the shared Rust text boundary synchronously after asynchronous initialization. Invalid options throw/reject; source errors return data.                          |
| Results and diagnostics | No writable output means `changed: false`; otherwise comparison is byte-for-byte. Diagnostics retain the supplied unsigned 32-bit source identifier and half-open UTF-8 spans. LSP converts positions to UTF-16. Messages remain human-readable. |
| Project configuration   | Native resolution is explicit and does not write. Callers inspect `ignored` and pass only language/format settings to text formatting. Web configuration helpers retain their documented restricted scope.                                       |
| Grammar/style           | Godot 4.3–4.7 profiles and existing compatibility boundaries remain explicit. Default style, punctuation/literal spelling and formatter snapshots are unchanged.                                                                                 |

## Resolved findings

### CLI argument validation and diagnostic routing

Invalid mode combinations previously reached execution and were reported as
`CLI_IO`; `init --config FILE` silently ignored the explicit file and could create
the default configuration. `--lsp` with a subcommand bypassed the selected JSON
reporter, and `--reporter=json` was silently ignored by the protocol server.

Options are now validated before configuration reads or writes. Unsupported
combinations return exit 2 with `CLI_ARGUMENT` / `configuration`, honoring the
selected reporter. `init`/`schema` reject `--config`; LSP rejects the JSON reporter
and subcommands. Stdin/file mixing and invalid virtual extensions use the same
argument path. Reporter detection stops at `--`, preserving literal path tokens.
Regression tests check JSON shape, stderr, unchanged source files and absence of
configuration writes, plus help/version's plain-text behavior.

### JavaScript validation and WASM declarations

The shared text validator previously skipped non-enumerable properties, allowing
invalid/unknown options to disappear. It now rejects them, like symbol properties
and values JSON would silently coerce or discard. Installed Node sync/async and
WASM regressions cover these inputs.

WASM initialization now rejects explicit `wasm: null`, keeping default loading
for omission/`undefined`. `TextConfig` declarations now include the `$schema` and
`schemaVersion: 1` metadata already returned by Rust. Packed consumer type tests
verify the fields and reject null initialization. Public `sourceId` documentation
states its 0–4294967295 range and default of 0.

### Version synchronization and validation

The version updater previously replaced the first matching version substring in
`Cargo.toml`, which could be a comment before `[workspace.package]`. It now targets
the actual field and verifies the planned workspace version. A fixture with both
a commented version and a commented section name covers planning, a write-free
dry run and the actual update.

Release checks now reject leading zeros and oversized numeric components in the
Marketplace version. Tests also reject WASM/core and extension/core version drift
and verify that a core update preserves the independent numeric extension version.

| Version               | Synchronization rule                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Core release          | Rust workspace/lock entries, exact internal dependencies, native npm root/platforms, WASM npm and extension `gdfmtVersion` move together. |
| Marketplace extension | Independent numeric SemVer with no leading zeros or prerelease suffix; maintained separately.                                             |
| Private tooling       | Root npm and docs package versions stay independent.                                                                                      |
| Schema formats        | Configuration and JSON-result `schemaVersion: 1` describe their formats, independently of the release number.                             |
| Release channels      | Prereleases use `next`; stable releases use `latest`, after frozen-artifact/consumer verification.                                        |

## Verification

- Rust regressions cover the CLI validation/reporting matrix, LSP behavior and
  the facade's empty/changed/error results with BOM, CRLF, supplementary Unicode
  and the maximum `SourceId`.
- `cargo test --workspace --all-features --locked` and
  `cargo test --workspace --no-default-features --locked`: each passed 172 tests,
  with two existing ignored tests. Rustfmt and Clippy with warnings denied passed.
- `rustup run 1.88.0 cargo check --workspace --all-targets --all-features --locked`
  passed, along with Schema generation consistency, compatibility and syntax
  coverage checks. `pnpm docs:build` passed for the bilingual documentation.
- `pnpm typecheck` and `pnpm test:release` passed; all 32 release-script tests
  passed, including the new version cases. `pnpm release:check` passed without
  changing the repository version.
- `pnpm test:npm` passed all eight installed `darwin-arm64` consumer tests,
  including ESM/CJS declarations, all profile fixtures, sync/async diagnostics and
  byte-identical npm/standalone CLI output. `pnpm verify:npm --local` verified the
  local receipt and explicitly recorded an incomplete platform matrix.
- `pnpm test:wasm` passed 1,465 fixture/profile cases in Node and Chromium, Worker
  and limit checks, strict options, null initialization and installed declarations.

Full project trials, pinned-engine comparisons, all native platform/Node
combinations and editor lifecycle acceptance remain separate checklist items.
This review does not publish, bump the real release version or validate a final
tag. Desktop/Web editor behavior and differences are covered by the subsequent
[editor review](0.1.0-editor-contract-review.md).
