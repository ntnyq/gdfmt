# 0.1.0 desktop and Web editor contract review

[简体中文](../zh/research/0.1.0-editor-contract-review.md)

Reviewed on 2026-10-23 against the `0.1.0-alpha.6` working tree, based on
`6c11445a329b688f27fd6693a3c6314ffeedce64` plus the preceding release reviews.
The editor contract is ready for 0.1.0 candidate validation. Default formatting
style and core formatter output are unchanged.

The subsequent [distribution review](0.1.0-editor-distribution-review.md) corrected
the initial source-manifest-only trust assumption below: packaged Web permits
untrusted-workspace `configPath`. It also distinguishes Web development-host
acceptance from browser-only end-user installation.

## Host behavior and differences

| Surface                       | Desktop                                                                                                                                                        | Web                                                                                                                                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime                       | Exact-version native stdio LSP; trusted workspaces can select an executable or npm CLI.                                                                        | Bundled WASM in a dedicated Worker; `serverPath` is ignored.                                                                                                                                                         |
| Configuration                 | CLI discovery, inheritance, overrides, EditorConfig and ignore selection.                                                                                      | JSON/JSONC discovery and relative inheritance inside the owning workspace only.                                                                                                                                      |
| Unsupported Web configuration | Supported by the native workspace layer.                                                                                                                       | `overrides` and `ignore`, including empty arrays, and discovered EditorConfig cause an error and no edits. Ignore files do not exclude opened documents.                                                             |
| Explicit configuration        | Absolute or workspace-relative paths.                                                                                                                          | Workspace-relative paths using `/`, confined to that root. Packaged Web permits workspace-relative `configPath` in untrusted workspaces too; desktop restricts it until trusted. Normal discovery remains available. |
| Documents                     | Local file workspaces and untitled buffers.                                                                                                                    | URI-based virtual workspaces and untitled buffers; untitled uses defaults, files outside an owning workspace are rejected.                                                                                           |
| Shared boundaries             | Both hosts format unsaved full buffers, discard stale results, support save/undo, map diagnostics to UTF-16 and preserve exact core output or return no edits. | Same.                                                                                                                                                                                                                |

Web limits remain 16 MiB of source, 1 MiB per configuration file, 16 MiB of
configuration reads per resolution, 32 simultaneous inheritance files, 128
applied configuration layers and 128 discovered directories. Repeated parents
are applied repeatedly and count toward the layer limit even when reads are cached.
Configuration changes are read on the next request; observed Web configuration
changes invalidate pending work. A failed Worker is replaced on a subsequent request.

## Corrected guidance and regression coverage

The previous error and guide suggested `lineEnding: "preserve"` without explaining
its limits. Preserve can avoid a conflict between structural newlines and retained
bytes for uniform input, but cannot guarantee uniform output from already mixed
input. The error now makes that distinction and directs remaining mixed output
to the CLI. Documentation also clarifies that VS Code may normalize line endings
when loading the file, before gdfmt sees the buffer. Actual uniform core output,
rather than the requested structural EOL, continues to determine buffer EOL.

Both real Extension Host suites now reject mixed LF/CRLF and bare-CR output even
under preserve, leave unchanged output alone, and check empty, partial and
full-document ranges. Neither host registers a range provider; the LSP rejects
range and multi-range methods with `-32601` and still accepts a later full-document
request. No range fallback, project analysis or semantic fix is added.

Web regressions additionally cover unsupported/invalid configuration, missing
parents, cycles, escaping the owning workspace, absolute/URL/backslash paths,
explicit path restrictions, ignore-file behavior, the 32-file inheritance boundary,
the 128-layer boundary with repeated cached parents, and oversized configuration.
Existing regressions retain protected regions, both multiline quote styles, EOL
conversion, Unicode diagnostics, configuration invalidation, nested workspace
ownership, save/undo and restart coverage.

No formatter or configuration acceptance defect was found in these reviewed
paths. The corrections concern error guidance, documented trust restrictions and
missing boundary regressions.

## Verification

- `cargo test -p gdfmt_cli --test lsp --locked`: five tests passed.
- Both editor TypeScript checks and the four Web Worker lifecycle/unit tests passed.
- `pnpm test:vscode:web`: Chromium Web Extension Host passed with a virtual
  filesystem and no cross-origin isolation, including the new boundary cases.
- `pnpm test:vscode`: VS Code 1.96.4 on macOS ARM64 passed with both workspace
  folder orders, including shared range/EOL regressions and save/undo checks.
- Rustfmt and the bilingual documentation build passed.

These checks cover the current local hosts, not all native platforms or a final
release tag. Candidate CI matrices, Godot Tools coexistence, project trials and
publication remain separate release checklist items.
