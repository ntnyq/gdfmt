## Save/undo acceptance follow-up

Two earlier PR macOS ARM64 jobs saved unformatted text:
[first failure](https://github.com/ntnyq/gdfmt/actions/runs/39969998748/job/120469844279),
[notification-synchronized failure](https://github.com/ntnyq/gdfmt/actions/runs/39971972425/job/120476725747).
Waiting for document-change notifications alone was insufficient. Temporary boundary
tracing did not reproduce it, so the exact internal VS Code trigger remains unconfirmed.

Acceptance now uses fresh isolated profiles/extensions and checks built-in save
readiness before activating gdfmt. An independent plaintext probe waits within a
bounded deadline for trailing-whitespace trimming and checks disk bytes. VS Code
1.96.4 registers trimming and format on save in the
[same participant component](https://github.com/microsoft/vscode/blob/1.96.4/src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts#L422).
The probe never calls gdfmt. Each GDScript save remains a single operation and must
produce exact buffer/disk contents; no failed formatting case is retried. Save/undo
assertions require both completed actions and exact text, including full undo
restoration, with bounded failure timeouts.

Temporary tracing, debug flags and reduced-reproduction paths are removed. Native
extension runtime/default formatter implementation are unchanged. Only complete CI
on the uninstrumented source counts for acceptance.
