# 0.1.0 current Trusted Publisher and account review

[简体中文](../zh/research/0.1.0-trusted-publisher-review.md)

Reviewed on 2026-10-23 against the `0.1.0-alpha.6` working tree based on
`6c11445a329b688f27fd6693a3c6314ffeedce64`. This follow-up to the
[registry readiness review](0.1.0-registry-readiness-review.md) queried all fifteen
packages individually and checked available account sessions. No publication,
dist-tag write, login, trust configuration change or credential inspection was
performed. The owner subsequently reported that publishing configuration is
complete. This confirmation supersedes the setup-action request below; the
tables preserve the earlier query results rather than claiming fresh API reads.
Field-level and account-readiness evidence has not been archived, and the new
candidate publication/install gate remains open.

## Results

Public ownership is still `ntnyq` for all eight crates and public maintainer
metadata is still `ntnyq` for all seven npm packages. All have the existing
alpha.6 publication evidence. However, current administrative settings are
unreadable in the available sessions: every crate query returned **403**, and
every npm trust query returned **E401**. Those results mean **unverified**, not
missing publishers or loss of package ownership.

Authentication failures do not prove that the account has disabled 2FA, an
unverified email or insufficient package rights. A browser login and CLI login
are separate sessions; completing one does not authenticate the other. The
existing CI uses OIDC and needs no new long-lived publishing token.

## Actions that still need ntnyq

1. **Sign in to both registries as the package owner.** In your browser, use
   [npm Sign In](https://www.npmjs.com/login) and
   [crates.io](https://crates.io/) → Log in with GitHub. Complete any account
   verification prompts yourself. Alternatively, use `npm login` locally for
   CLI administration; successful CLI login alone does not verify OIDC rights.
2. **Inspect the eight crate Settings → Trusted Publishing entries.** Every
   crate needs the expected GitHub binding below. Confirm the account email is
   verified and that bootstrap publishing tokens have been revoked. The
   [official crates.io guide](https://crates.io/docs/trusted-publishing) describes
   the settings; private adapters and `xtask` remain outside this review.
3. **Inspect all seven npm package Settings, including WASM.** Check the same
   binding, current configuration status and both **Allow npm publish** and
   **Allow npm dist-tag**. Confirm account email/2FA, per-package write access,
   publishing-access policy and bootstrap-token revocation. A stage-only
   publisher does not match this repository's direct-publication workflow.
4. **Record non-secret results.** For each package, record provider, owner/repo,
   workflow filename, environment, configuration status, the two npm permission
   booleans and review date. For the account, record only the username and
   email-verified/2FA/token-revocation confirmation, not addresses or credentials.
   Once signed in, the agent can continue reading the settings without changing
   them. A permission mismatch needs correction before a separately authorized
   release; this audit does not alter it.

| Required binding        | Expected value for every package |
| ----------------------- | -------------------------------- |
| Provider                | GitHub Actions                   |
| Repository owner / user | `ntnyq`                          |
| Repository              | `gdfmt`                          |
| Workflow filename       | `release.yml`                    |
| Environment             | `release`                        |

Do not recreate a working publisher merely to perform this audit. Newly created
npm configurations need their first successful new-version publication within
two days; skipped existing versions do not validate them. After the owner review,
the separate candidate publication/install gate still remains. No publication or
tag mutation should be used to close the read-only review.
