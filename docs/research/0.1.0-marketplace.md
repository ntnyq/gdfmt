# 0.1.0 Marketplace stable rollout

[简体中文](../zh/research/0.1.0-marketplace.md)

Date: **2026-10-26**. Extension **0.2.1**, bundled core **0.1.0**.
The six original frozen VSIX files have been uploaded to
[Marketplace](https://marketplace.visualstudio.com/items?itemName=ntnyq.gdfmt).
All six targets passed Gallery validation and exact download-integrity checks.
macOS ARM64 fresh installation, explicit prerelease-to-stable switching and the
Chromium Gallery harness passed. [Machine-readable evidence](0.1.0-marketplace.json)
records the hashes, versions, flags and consumer scope.

## Version identity

The core version and numeric VS Code extension version are independent:

| Distribution stage                                | Extension version | Bundled core    |
| ------------------------------------------------- | ----------------- | --------------- |
| Historical Marketplace prerelease                 | `0.1.0`           | `0.1.0-alpha.6` |
| rc.1 GitHub-only prerelease VSIX                  | `0.2.0`           | `0.1.0-rc.1`    |
| Stable GitHub VSIX, then this Marketplace rollout | `0.2.1`           | `0.1.0`         |

Extension `0.2.1` was selected when preparing the stable frozen artifacts, after
extension `0.2.0` had been used for rc.1. Marketplace does not require the jump to
`0.2.x`; this rollout retained the previously accepted artifact identities.
Cargo/npm packages and tag `v0.1.0` still identify core `0.1.0`. The extension
manifest uses `version: "0.2.1"` and `gdfmtVersion: "0.1.0"`.

## Gallery and consumers

Gallery archive availability can precede validation. The publisher requires the
`Validated` version flag as well as matching Gallery SHA-256 metadata, then
downloads every target and compares its bytes with the frozen archive. An early
desktop attempt correctly failed while Gallery still reported no stable version.

Installed-consumer evidence is scoped to the hosts actually exercised:

- macOS ARM64, VS Code **1.96.4**: default stable Gallery installation in a fresh
  profile; extension/core versions and bundled server version checked.
- Historical Gallery prerelease **0.1.0** to stable **0.2.1**: explicit unversioned
  stable installation using `--force`, in an isolated profile. This does not claim
  background automatic updates; exact-version installs are pinned by VS Code.
- Desktop consumers use a separate test-driver extension. gdfmt is installed
  from Gallery and must activate, format an unsaved buffer and format again after
  restarting its server.
- Web acceptance uses the pinned Chromium Web Extension Host and a stable Gallery
  `extensionIds` request, with no local gdfmt development extension. It checks
  extension/core identity, activation, formatting and Worker restart without
  cross-origin isolation. This is Gallery loading in the test harness, not a
  persisted vscode.dev profile.
  The local test-web harness requires its documented `--disable-web-security`
  option for external CDN resources. This applies only to the disposable test
  browser; it does not establish production-origin CORS behavior. Original Web CI
  retains its browser-security-enabled staged-extension checks.

Other native targets retain their original release CI/VSIX evidence. Downloading
them from Gallery does not establish a new installed host test on those platforms.

## Repeatable publication and recovery

`pnpm release:publish:marketplace` is read-only by default. It requires a reviewed
manifest digest and revision, validates the entire frozen set and Gallery history,
and uploads only with `--execute`. It refuses prerelease version reuse, stale
versions, incomplete target sets, missing acceptance and changed bytes. Recovery
skips existing matching versions and reconciles uncertain writes before continuing.
The report records uploads separately from validated/downloaded targets.

Run installed consumers with `pnpm test:vscode:marketplace`, add
`--upgrade-from 0.1.0` for the historical transition or `--web` for Chromium.
See [maintainer commands](https://github.com/ntnyq/gdfmt/blob/main/RELEASING.md#marketplace-stable-rollout).

The frozen Marketplace README retains its prepublication status text; current
installation guidance lives in the [integration guide](../guide/integrations.md).
Refreshing the packaged README requires a future extension version and new frozen
artifacts. The independent owner-account email/2FA/bootstrap-token audit from the
core release remains open; this rollout does not attest those account settings.
