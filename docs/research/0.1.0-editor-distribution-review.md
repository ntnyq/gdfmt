# 0.1.0 Marketplace and VSIX readiness review

[简体中文](../zh/research/0.1.0-editor-distribution-review.md)

Reviewed on 2026-10-23 against the `0.1.0-alpha.6` working tree based on
`6c11445a329b688f27fd6693a3c6314ffeedce64`. This is a distribution plan and
readiness review; it does not publish or change either version number.

## Recommendation for 0.1.0

Use the six frozen GitHub Release VSIX assets as the release delivery baseline.
Native users can install the appropriate asset directly. Keep Marketplace stable
publication a separate follow-up that does not block the core release. It may
accompany 0.1.0 once the steps below pass, otherwise the existing Marketplace
prerelease remains available and must not be described as the final core release.
For browser-only users, that distinction matters: the Web artifact is not a
promise of local VSIX installation in every browser-based VS Code product.

## Public Marketplace state

The public query `pnpm exec vsce show ntnyq.gdfmt --json` found the existing
[listing](https://marketplace.visualstudio.com/items?itemName=ntnyq.gdfmt): numeric
extension version **0.1.0**, marked **prerelease**, on `darwin-arm64`, `darwin-x64`,
`win32-x64`, `linux-x64`, `alpine-x64` and `web`. Gallery manifests for macOS ARM64
and Web both report core **0.1.0-alpha.6**. Thus “no Marketplace listing yet” and
“extension 0.1.0 means stable core 0.1.0” would both be incorrect.

This read-only public result proves a previous publication, not the current
operator's publisher membership or working authentication. The repository has
packaging and release attachment jobs, but no Marketplace publishing job or
recovery/installation evidence for a future stable Gallery upload.

Microsoft requires distinct numeric versions for prerelease and regular uploads,
and supports publishing existing platform VSIX packages. Plan all six targets
under one new numeric version; authenticate and publish the frozen bytes rather
than rebuilding from `editors/vscode/`. See the
[official publishing guide](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#pre-release-extensions).

## What is already verified

The inspected local macOS and Web VSIX archives match their recorded SHA-512.
Both have identity `ntnyq.gdfmt`, numeric version `0.1.0`, core `0.1.0-alpha.6` and
the prerelease flag. Native includes `main` and the executable without `browser`;
Web includes `browser`, Worker and WASM without `main` or a native executable.
Workspace dependencies are removed during staging.

The installed-archive smoke check uses an isolated VS Code 1.96.4 profile and
extension directory: install the macOS ARM64 VSIX, list `ntnyq.gdfmt@0.1.0`, and
check the installed native executable's exact core version. This does not change
the user's profile or prove final-candidate or cross-platform acceptance.
The existing host tests load development/staged directories; they do not by
themselves prove installation of a frozen VSIX or installation from Gallery.

A second isolated macOS ARM64 check installed `ntnyq.gdfmt@0.1.0` from Gallery
with the prerelease option, listed it and verified the installed executable as
`gdfmt 0.1.0-alpha.6`. This establishes the existing preview installation route,
not a future stable upload or its upgrade path.

## Corrected installation and trust guidance

The supported VSIX workflow is described in the
[official installation guide](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#install-from-a-vsix);
VSIX-installed extensions have automatic updates disabled by default. Verify the
core using **gdfmt: Show Version**, not only the numeric extension version.

The tested VS Code 1.96.4 implementation exposes local VSIX installation when a
local or remote extension-management server exists; a browser-only Web host is
not sufficient. See the
[pinned command registration](https://github.com/microsoft/vscode/blob/1.96.4/src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts#L804-L838).
Microsoft documents [hosted-location sideloading](https://code.visualstudio.com/api/extension-guides/web-extensions#test-your-web-extension-in-vscode-dev)
as a developer test route. The repository's `pnpm test:vscode:web` validates a
staged development host, not an end-user `vscode.dev` install.

Archive inspection also corrected an earlier source-manifest-only assumption:
`stageExtension(..., 'web')` replaces capabilities with full untrusted/virtual
workspace support. Web `configPath` is allowed in untrusted workspaces, subject
to the same relative-path and owning-workspace limits. Desktop alone restricts
workspace `configPath` and custom executables until trusted. Guides, release
notes and earlier review descriptions have been corrected accordingly.

## Remaining stable Marketplace preparation

1. Verify current publisher membership and a supported publishing identity;
   public metadata does not establish either. Review listing text, support links
   and stable-version availability.
2. With the final core `0.1.0`, select a new numeric extension version (proposed
   `0.2.0`, subject to a fresh Gallery check), then rebuild/test/freeze all six
   variants together. Do not republish Gallery prerelease `0.1.0` as stable.
3. Add or document a separately authorized publishing procedure using the frozen
   VSIX files. Record per-target results and recovery for partial uploads;
   Cargo/npm Trusted Publishers do not publish Marketplace extensions.
4. Verify stable Gallery target selection and clean-profile installation for
   desktop, a remote host and browser-only Web, plus formatting and version
   reporting. Check the prerelease-to-stable update path independently.
5. Announce Marketplace stable availability only after those checks pass.
   Until then, retain the native VSIX route and accurately label the existing
   Gallery prerelease and Web development/sideloading paths.

An icon/extension changelog may improve the listing, but their absence is not
treated as proof that publishing is impossible. No publisher credentials were
read and no Gallery write, version bump or user-profile installation is part of
this review.
