## 结果

八个 crate 的公开 owner 和七个 npm 包的公开 maintainer 仍均为 `ntnyq`，
都有既有 alpha.6 发布证据。但当前管理设置在可用会话中无法读取：八个 crate

不能据此认定 publisher 缺失或包所有权丢失。

| 检查                             | 结果                    | 仍需 owner 核对                              |
| -------------------------------- | ----------------------- | -------------------------------------------- |
| `npm whoami`                     | E401                    | 当前 registry 身份；此命令不是 OIDC 测试。   |
| `npm profile get`                | E401                    | 邮箱已验证、账号 2FA 已启用。                |
| `npm access list packages ntnyq` | E401                    | 七个包逐项具备 read-write 权限。             |
| npm 浏览器会话                   | 显示 Sign In / Sign Up  | owner 登录及包 Settings 访问。               |
| crates.io 浏览器会话             | 显示 Log in with GitHub | owner 登录、邮箱验证及 crate Settings 访问。 |
| 首次发布 token                   | 未读取或改动            | 确认旧发布 token 已撤销。                    |

认证失败不能证明账号关闭了 2FA、邮箱未验证或包权限不足。浏览器与 CLI 登录
属于不同会话，完成一处登录不会让另一处自动认证。现有 CI 使用 OIDC，不需要
新增长期发布 token。

## 仍需 ntnyq 操作的事项

1. **以包 owner 身份登录两个 registry。** 浏览器使用
   [npm Sign In](https://www.npmjs.com/login) 和 [crates.io](https://crates.io/)
   → Log in with GitHub，自己完成账号验证提示。也可在本地用 `npm login`
   供 CLI 管理查询；CLI 登录成功本身不能验证 OIDC 权限。
2. **检查八个 crate 的 Settings → Trusted Publishing。** 每个包都应存在下表
   对应的 GitHub 绑定，同时确认账号邮箱已验证、首次发布 token 已撤销。
   设置入口见 [crates.io 官方指南](https://crates.io/docs/trusted-publishing)，
   私有适配 crate 和 `xtask` 不在核对范围内。
3. **检查全部七个 npm 包的 Settings，包括 WASM。** 核对同一绑定、配置当前状态，
   并确认 **Allow npm publish** 与 **Allow npm dist-tag** 都开启。核对账号邮箱/
   2FA、各包写权限、Publishing access 策略和首次发布 token 撤销情况。
   仅允许 stage 的 publisher 不符合本仓库的直接发布流程。
4. **记录非秘密结果。** 每个包记录 provider、owner/repo、工作流文件名、环境、
   配置状态、两项 npm 权限布尔值及核对日期；账号只记录用户名及邮箱已验证/
   2FA/token 撤销的确认，不记录地址或凭据。登录后可继续由 agent 只读检查设置。
   权限不一致需要在另行授权的发布前修正，本轮不会修改。

| 必需绑定                | 每个包的预期值 |
| ----------------------- | -------------- |
| Provider                | GitHub Actions |
| Repository owner / user | `ntnyq`        |
| Repository              | `gdfmt`        |
| Workflow filename       | `release.yml`  |
| Environment             | `release`      |

不要为了审查重建正常工作的 publisher。npm 新配置需要在两天内首次成功发布
新版本，跳过已有版本不能完成验证。owner 核对完成后，仍保留独立的候选发布/
安装验收门槛，不通过实际发布或 tag 修改来完成这轮只读审查。
