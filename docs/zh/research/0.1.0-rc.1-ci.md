## 干净源码试用与产物

独立 checkout 在测试前后均干净，没有复制本地设置。使用 Python 3.12.14、锁定
的 gdtoolkit 4.5.0、固定 Godot 4.7.2 和 Rust 1.98，Python hash seed 为 131，
不带 `--record-review`。含真实 Python 桥的 14 项守卫全部通过。完整试用接受
605/606 个脚本与全部 2,420 种不变量布局：一个已知源码错误、九个比较器拒绝、
67 个相同输出、529 个已解释差异、零未解释差异，606 个审查条目全部未变。
四份报告 hash 与此前不同 Python hash seed 的候选试用一致。

八个公开 crate 使用
`cargo package --workspace --exclude gdfmt_napi --exclude gdfmt_wasm --exclude xtask --registry crates-io --locked`
完成打包与编译，没有 `--allow-dirty`；Cargo VCS 元数据匹配源码且没有 dirty 标记。

[产物证据](../../research/0.1.0-rc.1-artifacts.json)记录源码、工作流/artifact ID、ZIP
SHA-256、crate/试用报告 hash 和三份本地 bundle 清单 hash。18 份 push 归档包括
十份原生消费者、一份完整矩阵、一份 WASM、六份 VSIX。ZIP digest 匹配 GitHub
记录，内部回执匹配干净源码、版本及 tarball/VSIX 精确字节。PR 合并预览回执使用
合成 merge revision，不混入精确源码 bundle。

本机完整 `pnpm verify:npm` 通过，具有十份回执与 `completeMatrix: true`。
`pnpm release:prepare` 验证并组装七份 npm tarball、八份 crate 归档、六份 VSIX。
四个桌面目标均通过隔离 VSIX 安装、扩展/核心版本、安装后的 server 字节比较、
`--version` 和 stdin 格式化。桌面冻结新增要求 `installedVsixPassed: true`，并回归
测试缺失/false 回执的拒绝。Alpine 保留原生 smoke，Web 保留虚拟文件系统宿主；
staging Web 测试不代表最终用户的浏览器安装路线已验证。

本地 bundle 用于验证演练，不能替代绑定 tag 的正式冻结。Registry 安装示例仍
保留已发布版本/渠道。

## 保存与撤销验收后续

此前两次 PR macOS ARM64 job 保存了未格式化文本：
[首次失败](https://github.com/ntnyq/gdfmt/actions/runs/39969998748/job/120469844279)、
[增加通知同步后仍失败](https://github.com/ntnyq/gdfmt/actions/runs/39971972425/job/120476725747)。
仅等待文档变更通知不充分。临时边界跟踪未复现，因此 VS Code 内部的精确触发点
仍未确认。

验收现在使用全新隔离 profile/扩展目录，在激活 gdfmt 前检查内置保存链路就绪。
独立纯文本探针在有界时间内等待尾随空白清理生效，并检查磁盘字节。VS Code
1.96.4 在[同一个参与者组件](https://github.com/microsoft/vscode/blob/1.96.4/src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts#L422)
注册空白清理与保存格式化。探针不调用 gdfmt；每次 GDScript 保存仍只有一次操作，
必须得到精确缓冲区/磁盘内容，不重试失败格式化用例。保存/撤销断言同时要求动作
完成和精确文本，包括完整撤销恢复，并保留有界失败超时。

临时跟踪、调试标记和精简复现路径已移除。原生扩展运行时/默认 formatter 实现
未变，仅无跟踪源码的完整 CI 计入验收。
