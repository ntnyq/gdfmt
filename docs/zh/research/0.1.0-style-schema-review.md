## 建议保留的默认风格

解析后的宿主默认值、生成 Schema 的描述、公开 JavaScript 类型声明和
[配置指南](../guide/configuration.md)在以下 14 个格式化字段及取值上保持一致：

| 字段                        | 默认值   | 支持的取值                  |
| --------------------------- | -------- | --------------------------- |
| lineWidth                   | 100      | 40–320                      |
| indentStyle                 | tab      | tab / space                 |
| indentWidth                 | 4        | 1–8                         |
| lineEnding                  | lf       | lf / crlf / preserve        |
| maxBlankLines               | 2        | 0–5                         |
| finalNewline                | true     | 布尔值                      |
| arrayLayout                 | auto     | auto / multiline / preserve |
| dictionaryLayout            | auto     | auto / multiline / preserve |
| enumLayout                  | auto     | auto / multiline / preserve |
| dictionarySpacing           | compact  | compact / spaced            |
| trailingCommaLayout         | auto     | auto / multiline            |
| blankLinesAroundDefinitions | preserve | preserve 或整数 0–5         |
| lambdaBodyStyle             | auto     | auto / multiline            |
| inlineCommentSpacing        | 1        | 整数 1–4                    |

保留紧凑字典、按宽度布局集合、简单 lambda 内联、行尾注释前一空格，以及受
`maxBlankLines` 限制的原有定义间隔。修改这些默认值会改变已经审查过的输出；
现有显式选项足以表达其他偏好。

继续保留有效标点和字面量词形。例如带尾逗号的短数组可以保持为 `[1, 2,]`；
增删逗号、引号或分号需要单独的等价校验契约。注释和 formatter-off/on 字节保留
优先于布局偏好。

纯 Rust formatter 默认使用 `LineEnding::Preserve`，解析后的宿主配置使用 LF，
[格式化说明](../reference/formatting.md)已记录这个区别，建议继续明确保留。
CLI、Node 与 WASM 在配置解析后共享 `gdfmt_config::format_request`，这里没有
意外的跨宿主默认值差异。

## P2 已解决：整数值数字写法

原差异位于 `crates/gdfmt_config/src/lib.rs` 的各无符号整数字段与
`BlankLinesAroundDefinitions::Count`。

```json
{ "format": { "lineWidth": 100.0 } }
```

在原审查基线上，Schema 接受这个值，`parse_config` 却将它作为浮点数拒绝，
提示需要 `u16`。在此配置下运行 `gdfmt explain-config sample.gd`，退出码为 2。
`100` 可以通过，`1e2` 与 `100.0` 有相同问题。

探针也在 `indentWidth: 4.0`、`maxBlankLines: 0.0`、`inlineCommentSpacing: 1.0`、
`blankLinesAroundDefinitions: 2.0`、`schemaVersion: 1.0` 和
`overrides[0].format.lineWidth: 100.0` 上复现了差异。原有配置矩阵没有覆盖这些写法。

共享字段反序列化现已接受现有范围内、值为整数的小数/指数写法。转换前检查整数性
和无符号数范围，再保留目标整数类型的范围检查及配置校验。真正的小数、越界值、
字符串、`null` 和不支持的 Schema 版本仍会被拒绝，重复键拒绝与字段路径诊断保留。
回归测试覆盖基础字段、overrides、合并、浏览器辅助 API 和 CLI 继承配置。
解析后的配置序列化为规范整数，默认值与字段名称不变。

## P2 已解决：行宽边界的公开描述

`crates/gdfmt_formatter/src/layout.rs:537` 将二元、条件、cast 与类型测试表达式用
空格拼接；成员/调用链也没有通用断点。格式化/兼容性文档和 `lineWidth` 的 Schema
描述原先只提到了不可拆分 token/类型，没有说明这些表达式。

在 `lineWidth: 100` 下，下面的输入会输出为 112 列的一行，不产生诊断：

```gdscript
var result = first_value + second_value + third_value + fourth_value + fifth_value + sixth_value + seventh_value
```

探针中的六次方法调用链保持为 118 列。给二元表达式加括号后，外层 group 能换行，
但内部表达式连同缩进仍有 103 列。在宽度 40 下也能复现相同限制。
具有受支持元素断点的调用参数与嵌套集合可以正常换行。

中英文现已说明：`lineWidth` 是在受支持断点上的目标宽度，长表达式/调用链、保留的
注释/字面量、类型引用和保护区域都可能超宽，Rust 字段文档与重新生成的 Schema
描述同步。回归测试锁定宽度 40/100 下长表达式/调用链的现有输出与验证、幂等行为。
通用表达式换行仍是后续工作，不会为了满足行宽而插入括号或反斜杠。

## 回归覆盖与剩余范围

- `crates/gdfmt_config/tests/config.rs` 对比整数、小数和指数写法在数值边界上的
  Schema/运行时接受结果，覆盖基础字段和 overrides，检查规范化输出、默认值、
  零/false 合并、无效值、重复键与字段路径。
- `crates/gdfmt_config/tests/text.rs` 覆盖直接文本格式化、浏览器 JSONC 配置解析与
  层合并，包括无效继承值。
- `crates/gdfmt_cli/tests/cli.rs` 通过 `explain-config` 与 stdin 格式化，验证
  小数/指数写法的继承配置与 overrides。
- `crates/gdfmt/tests/layout_boundaries.rs` 验证两种宽度下长表达式/调用链的精确输出、
  正确性校验和幂等性；原有 formatter 快照继续作为默认风格基线。

初次审查通过了 49 项聚焦测试，并查看 16 类输入在 40/100 两种宽度下的输出。
