## Gallery 与消费者

Gallery 能下载 VSIX 时，验证可能仍未结束。发布脚本同时要求版本具备
`Validated` 标记和匹配的 Gallery SHA-256 元数据，再下载每个目标核对原始
冻结字节。早期桌面安装尝试在 Gallery 尚无可用正式版本时按预期失败。

安装验收仅覆盖实际运行的宿主：

- macOS ARM64、VS Code **1.96.4**：全新隔离配置通过默认 Gallery 正式版入口
  安装，核对扩展/核心及内置程序版本。
- 历史 Gallery 预发布 **0.1.0** 转正式版 **0.2.1**：隔离配置中使用无版本号的
  正式安装配合 `--force` 显式切换。不据此声称后台自动升级已验证；VS Code
  会固定精确版本安装。
- 桌面消费者使用独立测试驱动扩展，gdfmt 本身从 Gallery 安装；检查激活、
  未保存缓冲区格式化，以及重启服务后的再次格式化。
- Web 使用固定的 Chromium Web Extension Host，通过正式 Gallery `extensionIds`
  请求加载扩展，不注入本地 gdfmt 开发扩展。检查扩展/核心身份、激活、格式化
  和 Worker 重启，且无跨源隔离。这是测试宿主中的 Gallery 加载，不代表
  vscode.dev 的持久用户配置安装。
  本地 test-web 宿主按其文档使用 `--disable-web-security` 访问外部 CDN，
  仅影响此次临时浏览器，不据此证明生产域名的 CORS 行为。原始 Web CI
  仍保留启用浏览器安全检查的 staging 扩展测试。

其他原生目标保留原始发布 CI/VSIX 证据；从 Gallery 下载不能替代在对应平台上
新增一次安装宿主测试。

## 可重复发布与恢复

`pnpm release:publish:marketplace` 默认只读，要求已审查的 manifest hash 和
revision，检查整套冻结产物与 Gallery 历史，仅在 `--execute` 时上传。拒绝复用
预发布版本、过期版本、缺少目标、缺少验收及字节变化。恢复时跳过已存在且
匹配的版本；上传结果不确定时先回读确认，再继续。报告分别记录已上传与
已验证并下载核对的目标。

运行 `pnpm test:vscode:marketplace` 验收桌面；添加 `--upgrade-from 0.1.0`
验证历史版本切换，添加 `--web` 验收 Chromium。
命令详见[维护者流程](https://github.com/ntnyq/gdfmt/blob/main/RELEASING.md#marketplace-stable-rollout)。

冻结的 Marketplace README 保留上传前状态文字，当前安装说明见
[集成指南](../guide/integrations.md)。刷新已打包 README 需要后续扩展版本及新
冻结产物。核心发布中独立的账号邮箱/2FA/首次发布 token 撤销审计仍未完成；
本次上线不据此证明那些账号设置。
