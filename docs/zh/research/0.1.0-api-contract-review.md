## 已审查的契约

| 接口                | 契约                                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| CLI 入口            | 独立与 npm CLI 共享 `gdfmt_cli::run`，仅可执行入口负责退出进程；无命令/路径时格式化当前目录。                                             |
| CLI 退出码          | 成功为 0，源码/保护指令错误或只读格式差异为 1，参数/配置/I/O/内部失败或无输入为 2；批次取最高码。                                         |
| CLI 输出            | 人类可读错误走 stderr；JSON 报告走 stdout，Schema 版本为 1、span 为 UTF-8 字节；帮助/版本仍为纯文本，LSP 使用带帧头的 JSON-RPC。          |
| Rust facade         | 显式 `FormatRequest`，无配置发现或文件写入；可写输出必须通过重解析、语法/注释保留与幂等检查，`Some("")` 是成功的空输出。                  |
| JavaScript 文本 API | 原生同步/异步函数结果一致，异步工作进入 libuv；WASM 异步初始化后同步调用共享 Rust 文本边界。无效选项抛错/reject，源码错误返回数据。       |
| 结果与诊断          | 无可写输出时 `changed: false`，否则按字节比较；诊断保留传入的无符号 32 位源码标识及半开 UTF-8 span，LSP 转换为 UTF-16；消息文本面向人类。 |
| 项目配置            | 原生解析必须显式调用，不写文件；调用方检查 `ignored`，只将 language/format 交给文本格式化。Web 辅助 API 保持已记录的受限范围。            |
| 语法/风格           | 明确 Godot 4.3–4.7 profiles 与已有兼容性边界；默认风格、标点/字面量词形及 formatter 快照不变。                                            |

## 已解决的问题

### CLI 参数校验与诊断路由

非法模式组合原先进入执行阶段，被报告为 `CLI_IO`；`init --config FILE` 会静默
忽略显式路径，并可能创建默认配置。`--lsp` 搭配子命令绕过了选定的 JSON reporter，
`--reporter=json` 也会被协议服务忽略。

现在选项在读取配置或写入文件前校验，非法组合退出 2，按选定 reporter 输出
`CLI_ARGUMENT` / `configuration`。`init`/`schema` 拒绝 `--config`，LSP 拒绝 JSON
reporter 和子命令；stdin/文件混用与非法虚拟扩展名也使用统一参数诊断。
reporter 探测在 `--` 处停止，保留之后的字面路径含义。回归覆盖 JSON 结构、stderr、
源码不变、没有配置写入，以及帮助/版本的纯文本行为。

### JavaScript 校验与 WASM 类型声明

共享文本校验器原先跳过不可枚举属性，导致无效/未知选项消失。现在会像 symbol 属性
及 JSON 会静默转换/丢弃的值一样拒绝它们，原生同步/异步与 WASM 安装包均有回归覆盖。

WASM 初始化现在拒绝显式 `wasm: null`，仅在省略/`undefined` 时默认加载。
`TextConfig` 声明补上 Rust 已返回的 `$schema` 与 `schemaVersion: 1` 元数据；
安装包消费者类型检查验证这些字段并拒绝 null 初始化。公开 `sourceId` 说明明确了
0–4294967295 范围及默认值 0。

### 版本同步与校验

版本脚本原先替换 `Cargo.toml` 中首次出现的版本子串，可能改到 `[workspace.package]`
之前的注释。现在定位实际字段，并校验计划中的 workspace 版本。含版本注释与节名
注释的 fixture 覆盖了计划、无写入 dry run 和实际更新。

发布检查现在拒绝 Marketplace 版本中的前导零和过大的数字段。测试也拒绝 WASM/core
与扩展/core 版本漂移，并验证更新核心时保留独立的扩展数字版本。

| 版本                 | 同步规则                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| 核心发布版本         | Rust workspace/lock 条目、内部精确依赖、原生 npm 主包/平台包、WASM npm 与扩展 `gdfmtVersion` 同步。 |
| Marketplace 扩展版本 | 独立数字 SemVer，无前导零或预发布后缀，单独维护。                                                   |
| 私有工具版本         | 根 npm 与 docs 包版本独立。                                                                         |
| Schema 格式版本      | 配置与 JSON 结果中的 `schemaVersion: 1` 描述各自格式，与发布版本独立。                              |
| 发布渠道             | 预发布进入 `next`，正式版本在冻结产物/消费者验证后进入 `latest`。                                   |

  版本用例；`pnpm release:check` 通过，未修改仓库实际版本。
