# 0.1.0 桌面与 Web 编辑器契约审查

[English](../../research/0.1.0-editor-contract-review.md)

于 2026-10-23 审查 `0.1.0-alpha.6` 工作区，基于
`6c11445a329b688f27fd6693a3c6314ffeedce64` 及此前发布审查的修改。
编辑器契约可进入 0.1.0 候选版本验收，默认格式化风格与核心输出均未改变。

后续[分发审查](0.1.0-editor-distribution-review.md)修正了下方最初只看源码清单的
信任误判：已打包 Web 允许未信任工作区的 `configPath`，并区分了 Web 开发宿主
验收与纯浏览器最终用户安装。

## 宿主行为与差异

| 行为             | 桌面                                                                                                    | Web                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 运行时           | 版本精确匹配的原生 stdio LSP；受信任工作区可选择程序或 npm CLI。                                        | 专用 Worker 中的内置 WASM，忽略 `serverPath`。                                                                                      |
| 配置             | CLI 配置发现、继承、overrides、EditorConfig 和忽略选择。                                                | 仅支持所属工作区内的 JSON/JSONC 发现与相对路径继承。                                                                                |
| Web 不支持的配置 | 原生工作区层支持。                                                                                      | `overrides`、`ignore`（包括空数组）及发现到的 EditorConfig 均报错且不返回编辑；忽略文件不排除已打开文档。                           |
| 显式配置         | 绝对路径或工作区相对路径。                                                                              | 使用 `/` 的工作区相对路径，不能越过所属根目录。已打包 Web 在未信任工作区也允许相对 `configPath`；桌面端需要信任。常规发现仍可使用。 |
| 文档             | 本地文件工作区与未命名缓冲区。                                                                          | URI 虚拟工作区与未命名缓冲区；未命名文档使用默认值，没有所属工作区的文件被拒绝。                                                    |
| 共同边界         | 格式化未保存的全文缓冲区、丢弃过期结果、支持保存与撤销、诊断转为 UTF-16；精确保留核心输出或不返回编辑。 | 相同。                                                                                                                              |

Web 上限仍为源码 16 MiB、单份配置 1 MiB、每次解析读取配置总量 16 MiB、
同时继承文件 32 层、应用配置 128 层和发现目录 128 层。重复父配置会重复应用，
即使读取命中缓存也计入配置层数。每次请求重新读取配置；观察到的 Web 配置变化
使待处理结果失效。Worker 失败后在后续请求中重建。

## 修正说明与回归覆盖

原错误提示与指南推荐 `lineEnding: "preserve"`，但没有说明限制。对统一换行的输入，
preserve 可避免结构换行与保留字节冲突；对已混合换行的输入，则不保证输出统一。
错误提示现已区分这两种情况，并引导仍需混合换行输出的场景使用 CLI。文档还说明
VS Code 可能在载入文件时就统一换行，gdfmt 接收到的是载入后的缓冲区。缓冲区
EOL 仍由核心实际的统一输出决定，而不是直接套用结构换行配置。

两个真实 Extension Host 套件现均检查：即使使用 preserve，也拒绝混合 LF/CRLF
及孤立 CR 输出；核心输出未变化时保持缓冲区；空选区、局部选区和全文选区均没有
范围格式化 provider。LSP 对范围及多范围方法返回 `-32601`，后续全文格式化仍正常。
没有增加范围回退、项目分析或语义修复。

Web 回归还覆盖不支持或无效的配置、缺失父配置、继承环、越过所属工作区、
绝对路径/URL/反斜杠路径、显式路径限制、忽略文件行为、32 文件继承边界、
重复缓存父配置的 128 层应用边界及超大配置。现有测试继续覆盖保护区域、两种多行
引号、EOL 转换、Unicode 诊断、配置失效、嵌套工作区归属、保存/撤销和重启。

这些已审查路径没有发现 formatter 或配置接受行为的缺陷。本次修正集中在错误引导、
信任限制说明和缺失的边界回归。

## 验证

- `cargo test -p gdfmt_cli --test lsp --locked`：5 项测试通过。
- 桌面与 Web TypeScript 检查、4 项 Web Worker 生命周期/单元测试通过。
- `pnpm test:vscode:web`：Chromium Web Extension Host 在虚拟文件系统及无跨源
  隔离条件下通过，包含新增边界用例。
- `pnpm test:vscode`：macOS ARM64 上 VS Code 1.96.4 的两种工作区目录顺序均
  通过，包含共用范围/EOL 回归及保存/撤销检查。
- Rustfmt 与双语文档构建通过。

以上只验证当前本地宿主，不代表全部原生平台或最终发布标签验收。候选版本 CI
矩阵、Godot Tools 共存、真实项目试跑和发布仍是独立检查项。
