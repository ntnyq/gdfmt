## 已落实的保护与维护者权限

预期 REST 请求内容记录在
[`.github/repository-protection.json`](../../../.github/repository-protection.json)。
该文件供审查和记录配置，不会自动部署。

- `main` 要求 PR、检查对应的分支保持最新，以及讨论已解决。审查的 `main` SHA
  上已观察到现有全部 29 项检查成功，并绑定 GitHub Actions app `15368`，没有
  填入不存在的检查名称。覆盖 Rust quality/MSRV/tests、五种引擎 profile、npm
  十份原生消费者及 parity/scripts，以及七个 WASM/编辑器宿主 job。
- PR 审批人数为 `0`，不要求 code-owner 或最后一次推送审批。当前唯一协作者为
  管理员 `ntnyq`，无需第二位 reviewer 也能合并检查成功的 PR。禁用 force push
  和删除；明确设置 `enforce_admins: false` 保留管理员应急绕过，常规修改仍应
  通过检查成功的 PR 合并。
- 已启用的 [Version tags ruleset 25720774](https://github.com/ntnyq/gdfmt/rules/25720774)
  限制 `refs/tags/v*` 的创建、更新和删除，没有排除项。仓库 Admin（ID `5`）和
  Maintain（ID `2`）具备 `always` 绕过，普通 Write 权限没有例外。REST 回读与
  记录策略一致，GraphQL 返回了实际 `admin`/`maintain` 角色名和 `ALWAYS` 模式。
- `v-recovery-*` 适用相同维护者例外。恢复时不要移动已发布 tag，应复用冻结字节，
  需要时使用独立恢复 ref。现有 GitHub Release job 通过 `--verify-tag` 验证已有
  tag，无需创建 tag 的绕过权限；未添加 Actions/app 绕过。Environment、发布开关
  及 registry OIDC 配置均未改动。

配置后 `main` SHA 未变。通过 API 核对生效设置，没有推送、测试 tag 或 dispatch，
因此不声明新发布或恢复已经实测成功。job/矩阵变化时，需同步 JSON 记录和远端
必需检查名称。API 行为见
[GitHub 分支保护](https://docs.github.com/en/rest/branches/branch-protection#update-branch-protection)
及 [repository rulesets](https://docs.github.com/en/rest/repos/rules#create-a-repository-ruleset)。

## Trusted Publisher 契约与审查边界

源码中的两个 registry 发布 job 及 npm 恢复 job 使用 GitHub 托管 Ubuntu runner、
`environment: release` 和 `id-token: write`。**十五个发布单元各自**应配置：
owner/user `ntnyq`、仓库 `gdfmt`、工作流文件名 **`release.yml`**、环境
**`release`**。npm 还需要同时允许直接 `npm publish` 和 `npm dist-tag`。
固定 Node **24.0.0**、npm **11.21.0**、运行时守卫与 scoped dist-tag 补丁继续
保留；本轮只读审查未满足移除补丁的条件。

[当前逐包/账号审查](0.1.0-trusted-publisher-review.md)对全部发布单元重新查询：
八个 crates.io 请求均返回 **403**，七个 `npm trust list` 请求均返回 **E401**。
npm 身份/资料/权限请求也返回 E401，可访问的两个浏览器会话均未登录。八个 crate
公开的 `trustpub_only` 均为 `false`，属于可选加固状态，不能证明 token 存在或
已撤销。没有尝试交互登录或修改信任配置。这不代表 publisher 缺失或失效。
历史记录不能说明配置是否被删除/重建、
当前环境绑定和允许操作是否正确、账号 2FA/邮箱状态，或首次发布 token 是否已撤销。

需要已登录的包 owner 逐项核对八个 crate 和七个 npm 包的设置，包括
`@gdfmt/wasm`，只记录非秘密字段。npm 新建配置需要在两天内首次成功发布新版本；
跳过已有 alpha.6 字节不能完成验证。参见
[npm Trusted Publishers](https://docs.npmjs.com/trusted-publishers/) 和
[npm trust list](https://docs.npmjs.com/cli/v11/commands/npm-trust)。
crates.io 的[配置列表实现](https://github.com/rust-lang/crates.io/blob/main/src/controllers/trustpub/github_configs/list.rs)
要求身份认证与 crate 所有权。
