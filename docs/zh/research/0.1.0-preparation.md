加当前工作区未提交的版本和文档改动。本次未创建提交、tag、发布工作流、registry

证据为 `cleanSource: false`、`published: false`，不是最终冻结修订。

`pnpm release:version 0.1.0 --dry-run` 与实际本地更新通过。审查覆盖 workspace
版本、七项精确内部依赖、十一项 Cargo lockfile 记录、两个公开 npm manifest、
五项精确原生 optional 依赖和扩展 `gdfmtVersion`；生成的平台包继承 0.1.0。

本次未移动任何 registry 渠道。

扩展使用独立数字版本 **0.2.1**，高于 rc.1 GitHub VSIX 的 **0.2.0**，避免不同
内容共用同一个扩展版本。重新运行 `pnpm exec vsce show ntnyq.gdfmt --json`，
Gallery 六目标仅列出预发布 **0.1.0**，快照中 0.2.1 未占用，但这不预留版本，
任何上传前仍需复查。[VS Code 官方发布规则](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#pre-release-extensions)
要求数字版本，并要求 Gallery 预发布与正式上传使用不同数字版本。产物文件名仍按
核心版本为 `gdfmt-0.1.0-TARGET.vsix`；正式核心打包会移除 VSIX 预发布标记，
最终六目标冻结尚待完成。

格式化实现、默认风格、API 声明、配置契约与生成 Schema 均未改。安装文档保留
已发布 rc.1 的命令，0.1.0 发布说明仍标记草稿。历史 rc.1 报告和回执保留各自
原始修订及版本。

registry 解析尚未发布的 workspace 依赖；随后使用隔离临时 Cargo 配置、直接访问
