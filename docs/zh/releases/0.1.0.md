# gdfmt 0.1.0 发布说明

[English](../../releases/0.1.0.md)

**正式发布 — 2026-10-25。** 核心 **0.1.0** 已发布到 crates.io 与 npm `latest`，
GitHub 的六份冻结 VSIX 使用独立扩展版本 **0.2.1**。默认风格及公开 API/Schema
契约与 [0.1.0-rc.1](0.1.0-rc.1.md)保持一致。最终 tag 的完整 CI、干净项目试用、
registry 消费者及产物 hash 见[发布报告](../research/0.1.0-publication.md)。
Marketplace 正式发布独立跟进。

gdfmt 通过共享 Rust 核心格式化 UTF-8 GDScript `.gd` 文件。可写输出必须重新解析
成功、保持语法及注释关系，并在第二次格式化时产生完全相同的结果。发布范围包括
完整脚本格式化、项目配置、命令行检查和编辑器缓冲区集成。

## 支持的宿主

| 宿主         | 范围                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rust         | `gdfmt` facade 提供纯文本格式化，配置/工作区 crate 提供显式项目解析。最低支持 Rust 1.88、edition 2024；源码开发使用固定工具链。                    |
| CLI          | Cargo 包 `gdfmt_cli` 安装 `gdfmt` 命令：文件格式化、检查、差异预览、stdin、配置检查及 JSON 报告。                                                  |
| 原生 Node.js | `@gdfmt/gdfmt` 支持 ESM/CommonJS、TypeScript 声明、同步/异步文本格式化和配置解析。需要 Node 22.x 的 22.13+ 或 Node 24.x，保留 optional 原生依赖。  |
| 浏览器/WASM  | `@gdfmt/wasm` 支持浏览器 ESM 与 module Worker，异步初始化、同步格式化，无需共享内存或跨源隔离。也支持 Node 显式字节加载；浏览器验收使用 Chromium。 |
| 桌面编辑器   | 仅格式化的 stdio LSP 与 VS Code 1.96+ 桌面扩展，支持目标匹配的 SSH/WSL/容器扩展宿主；原生 VSIX 内置 formatter。                                    |
| Web 编辑器   | 独立的 VS Code Web VSIX，内置 WASM Worker，支持虚拟工作区、未保存缓冲区、保存格式化、撤销和 UTF-16 诊断。                                          |

原生 npm 包和桌面 VSIX 目标覆盖 macOS ARM64/x64、Windows x64 MSVC、Linux x64
glibc/musl。Linux glibc 产物以 Ubuntu 24.04 为基线，未验证更旧 glibc。包括远程
场景在内，VSIX 必须匹配扩展宿主的平台。安装已构建的原生 VSIX 无需额外安装
Node；选择工作区 npm CLI 时使用扩展宿主的 Node。0.1.0 建议以 GitHub Release 的冻结 VSIX 为交付基线，
Marketplace 正式发布独立跟进。现有 Marketplace 条目为预发布，不代表最终核心
版本；纯浏览器安装使用 Gallery 或受支持的开发侧载方式，详见编辑器设置。

详见[安装](../guide/index.md)、[Node](../reference/node.md)、
[WASM](../reference/wasm.md)和[编辑器设置](../guide/integrations.md)。

## Godot 语法版本

语法配置为 **4.3、4.4、4.5、4.6、4.7**，默认固定为 **4.7**。
请将 `language.godotVersion` 设为项目对应版本。Profile 检查已核验的语法引入
边界，例如 4.4 的类型化字典、4.5 的抽象声明/rest 参数，以及 4.6 的多行导出提示。

Godot 3.x、未知版本、`4.7.2` 等 patch 字符串和 `latest` 都不是可接受的配置值。
Profile 不代表完整 Godot 兼容性、项目分析或运行时等价，详见
[版本 gates](../reference/language-versions.md)和[兼容性](../reference/compatibility.md)。

## 默认格式化风格

本次审查保留已有预发布版本的默认风格：

| 设置             | 默认值与行为                                                   |
| ---------------- | -------------------------------------------------------------- |
| 行宽             | `100`，是列表/参数等受支持断点的目标，不是硬上限。             |
| 缩进             | Tab，显示宽度 `4`，用于代码块与续行。                          |
| 结构换行         | LF；非空文件末尾保留一个换行。                                 |
| 现有空行         | 最多 `2` 行；删除文件首尾空行。                                |
| 数组、字典、枚举 | `auto` 布局，在支持的断点按行宽展开。                          |
| 字典内部空格     | `compact`，单行大括号内部不额外填充空格。                      |
| 尾随逗号布局     | `auto`；保留现有逗号，不插入或删除。                           |
| 定义间距         | `preserve`，现有间隔仍受空行上限约束。                         |
| Lambda 函数体    | `auto`，简单且无注释的单条语句可保持行内，其他情况使用代码块。 |
| 行尾注释         | 代码与尾随注释间一个空格。                                     |

具名函数和控制流使用多行代码块。字面量词形、现有标点、BOM、注释文本/顺序/
附着关系、多行字符串和保护区域的字节保持不变。布局选项不会转换引号，也不会
为了换行增加括号。纯 Rust `FormatOptions` 默认保留源码换行；CLI/Node/WASM
配置默认使用 LF。

成对的独立注释 `# gdfmt: formatter-off` / `# gdfmt: formatter-on` 保留选定区域，
包括标记行。区域内容仍必须通过解析；嵌套或未配对指令不会产生可写输出。
详见[格式化](../reference/formatting.md)和[全部配置选项](../guide/configuration.md)。

## 从 gdformat 迁移

gdfmt 有自己的布局规则。相同行宽和缩进并不意味着与 gdtoolkit 的 `gdformat`
输出一致，两者配置文件不能互换。已有的 `gdlint` 或其他分析工具可以继续保留，
gdfmt 不替代 lint 规则。

1. 本地与 CI 固定同一 gdfmt 版本。从干净工作区开始，将首次格式化改动与行为
   修改分开提交。
2. 两种 gdfmt 配置文件名均不存在时，运行 `gdfmt init`，编辑生成的
   `.gdfmtrc.json`，选择项目的语法版本和布局。例如，采用两空格缩进的 Godot 4.5
   项目可使用：

   ```json
   {
     "schemaVersion": 1,
     "root": true,
     "language": { "godotVersion": "4.5" },
     "format": { "lineWidth": 100, "indentStyle": "space", "indentWidth": 2 }
   }
   ```

   手动转换配置；gdfmt 不自动发现 `gdformatrc` 或 `.gdformatrc`。下表中的旧配置和
   参数来自上游 [gdformat CLI/配置实现](https://github.com/Scony/godot-gdscript-toolkit/blob/master/gdtoolkit/formatter/__main__.py)：

   | 原 gdformat 配置                | gdfmt 对应方式                                                                            |
   | ------------------------------- | ----------------------------------------------------------------------------------------- |
   | `line_length` / `--line-length` | `format.lineWidth`，40–320 的整数。                                                       |
   | `use_spaces` / `--use-spaces`   | `format.indentStyle: "space"` 配合 `format.indentWidth`（1–8 的整数）；Tab 使用 `"tab"`。 |
   | `excluded_directories`          | 审查路径并手写 gitignore 风格的 `.gdfmtignore`，核对实际选中的文件。                      |
   | `safety_checks` / `--fast`      | 没有跳过验证的对应选项；gdfmt 始终校验可写输出。                                          |

3. 检查忽略规则及格式化抑制注释。原生发现遵守本地 ignore，始终排除 `.git`、
   `.godot`、`node_modules` 和 `target`，不会导入旧排除列表。需要保留精确布局时
   使用 gdfmt 的成对标记。运行 `gdfmt explain-config path/to/script.gd` 检查有效
   配置及路径是否被忽略。
4. 运行 `gdfmt --diff .`，重点审查注释、lambda、长行和保护区域，再运行
   `gdfmt .` 应用已审查的配置。预览存在格式差异时退出 1；退出 2 表示参数、配置、
   I/O/内部失败或没有选中输入。格式化后继续运行项目原有的 Godot 检查与测试。
5. 将 CI/hook 改为 `gdfmt --check .`，将 VS Code 的 GDScript 默认 formatter 设为
   `ntnyq.gdfmt`，避免同一批文件交替使用不同 formatter。检查干净时退出 0，源码/
   指令错误或格式差异退出 1，宿主/配置失败退出 2，多文件取最高退出码。

配置优先级依次为默认值、EditorConfig、JSON/JSONC 基础字段、匹配的 overrides，
采用转换后的配置前应检查实际结果。外部编辑器可通过
`gdfmt --stdin-filepath path/to/file.gd` 传递未保存缓冲区，仅在退出 0 时应用 stdout。
详见[文件选择](../guide/configuration.md#ignore-rules-and-input-selection)和
[CI/编辑器集成](../guide/integrations.md)。

## 已知限制

- 类型/名称解析、资源、继承/抽象 override 和运行时行为仍由 Godot 负责。注解值
  只做部分检查，也没有复现 Unicode 易混淆关键字安全检查。
- 长表达式/调用链、不可拆分 token/类型引用及保留的注释/字面量/保护区域可能超出
  行宽目标。不提供引号转换、逗号增删、lint 引擎或语义自动修复。
- 场景/资源文件、shader、嵌入式 GDScript 及 `namespace`/`trait` 声明不在支持范围内。
- 编辑器仅支持全文格式化。VS Code 无法无损表示混合 EOL 输出，桌面和 Web 都会
  拒绝这类编辑。统一换行输入可尝试 `preserve`；精确混合输出可能需要 CLI，且
  缓冲区载入时可能已经统一换行。
- Web 配置不能越过所属工作区，拒绝 `overrides`、配置 `ignore`（包括空数组）及
  发现到的 EditorConfig。忽略文件不排除已打开的 Web 文档。桌面工作区
  `configPath` 需要信任；已打包 Web 在未信任工作区也允许它，仍受相同目录边界
  限制，并忽略 `serverPath`。
- 宿主文本格式化的源码上限为 16 MiB。Web 配置限制为单文件 1 MiB、累计读取
  16 MiB、32 层继承、128 个应用层和 128 个发现目录。WASM 格式化阻塞调用线程，
  较大输入应使用 Worker；不承诺 Bun、Deno 或通用 WASI 宿主支持。

文本 API 在源码/内部验证失败时返回结构化诊断且无输出，非法参数抛错或 reject。
JavaScript span 是半开 UTF-8 字节偏移，LSP/编辑器位置为 UTF-16；仅在 API 输出
非 null 时应用结果。格式化/检查成功不能替代 Godot 项目验证。
